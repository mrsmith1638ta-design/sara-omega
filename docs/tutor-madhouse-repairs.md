# SARA tutor Madhouse repair

The Product Manager tutor and Accessibility Tutor share the guarded assessment runtime. Start the former with `uvicorn SARA_AI_Product_Manager_Adaptive_Tutor_UNIFIED:app` and the latter with `uvicorn accessibility_tutor:app` from this directory. Use separate persistent SQLite database paths for the two tutors. Both require `SARA_GENERATOR_URL`, `SARA_GENERATOR_TOKEN`, `ROAD_VERIFIER_URL`, `ROAD_VERIFIER_TOKEN`, and `SARA_TUTOR_HMAC_SECRET` (at least 32 bytes). The Accessibility Tutor supports `SARA_ACCESSIBILITY_DB_PATH`; the Product Manager tutor supports `SARA_TUTOR_DB_PATH`.

An existing trusted identity service must authenticate the learner and issue a short-lived signed learner token with the Python `issue_learner_token(learner_id, secret)` function. Supply `Authorization: Bearer <token>` to every learner route. Never expose token issuance as an unauthenticated HTTP route. Protect the shared signing secret and persist the databases on durable, access-controlled volumes. Neither tutor is deployable until real generator and ROAD contracts are bound and their evidence checks are validated.

Only the first answer submission changes mastery. Later retries can complete the question and reveal the explanation, but do not improve or worsen mastery. Scoring and attempt recording occur in one SQLite transaction. Answer positions are allocated from a shared four-position counter and are shuffled before serving. The novelty ledger rejects repeated prompts, answer logic, reasoning paths, and scenario signatures while permitting distinct questions under one learning objective. Previous databases with a unique objective constraint are migrated on initialization; back up persistent data before applying the new code.

Madhouse verification: `python -m pytest tests/test_madhouse_tutors.py -q` from the parent folder. The tests use mocked generator and ROAD responses for the full tutor flow, so they do **not** attest live ROAD quality, certification question validity, Pearson VUE algorithms, or deployment readiness. Accessibility standards and certification content need an independently maintained source registry and a real verifier that checks the cited evidence before any exam-resemblance or readiness claim.
