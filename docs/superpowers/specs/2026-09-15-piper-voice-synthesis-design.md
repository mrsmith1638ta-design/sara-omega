# SARA OMEGA Piper Voice Synthesis Design

## Purpose

Add a production voice-synthesis capability to SARA OMEGA using Piper while preserving the unified build's existing security, audit, and fail-closed boundaries.

SARA's default speaking identity is `sara_elegant_british_v1`: a British English female voice persona, professional and elegant in character, with measured pacing, clear articulation, and restrained variability. The implementation uses the Piper `en_GB-cori-high` voice. The persona description is a product character specification, not a claim about the recorded speaker's real age.

## Architectural Decision

Piper MUST NOT be imported into SARA OMEGA's core Python dependency set. Piper is GPL-3.0-or-later and its high-quality Cori model is large, so it will run as a separate internal voice service. SARA core communicates with that service over HTTP through a narrow adapter.

This design intentionally creates four isolated units:

1. `sara_unified.voice.profile` owns SARA's fixed voice persona and synthesis defaults.
2. `sara_unified.voice.client` owns the HTTP contract to the internal Piper service.
3. `sara_unified.app` exposes a governed SARA voice route and records audit evidence.
4. `voice_service` owns the Piper runtime, model loading, authentication, and WAV generation.

No Piper package or voice model is added to the main SARA image.

## Data Flow

1. An authorized SARA caller submits approved response text to `/v1/voice/synthesize`.
2. SARA validates authorization and input length.
3. SARA uses only the fixed `sara_elegant_british_v1` profile; callers cannot inject an arbitrary model path or voice.
4. SARA calls the internal Piper service with the configured shared service token.
5. The Piper service validates the token, synthesizes WAV audio with `en_GB-cori-high`, and returns `audio/wav`.
6. SARA records an audit event containing the profile name, character count, and SHA-256 of the text rather than storing the full spoken text in the audit event.
7. SARA returns the WAV bytes to the caller.

The Piper service has no decision authority, tool access, memory access, or governance authority. It converts text to audio only.

## Voice Profile

Profile ID: `sara_elegant_british_v1`

Piper model: `en_GB-cori-high`

Persona:

- British English
- female presentation
- professional executive register
- elegant, calm, articulate
- mid-30s in product character only
- measured rather than slow
- confident without theatrical emphasis
- restrained synthesis variation

Synthesis defaults:

- `length_scale = 1.08`
- `noise_scale = 0.55`
- `noise_w_scale = 0.70`
- `volume = 0.95`

These are SARA-owned defaults. External callers may submit text only in the first release; they may not override the voice model or synthesis parameters.

## SARA Core API

### `POST /v1/voice/synthesize`

Request body:

```json
{
  "text": "SARA OMEGA voice synthesis is online."
}
```

Authorization:

- requires `voice:synthesize`
- current unified local development operator receives this permission only when the existing local-operator mode is explicitly enabled
- production deployments continue to fail closed when no authorized identity is present

Success response:

- status: `200`
- content type: `audio/wav`
- body: WAV bytes generated by the Piper service

Failure behavior:

- `401` when the SARA caller lacks authorization
- `422` for empty text or text above the configured character limit
- `503` when voice synthesis is disabled or the Piper service is unavailable
- `502` when the Piper service returns an invalid or unsuccessful response

### `GET /v1/voice/profile`

Returns non-sensitive metadata for SARA's configured voice profile, including profile ID, language, model ID, and persona description. It does not expose service tokens or model filesystem paths.

## Configuration

Extend `sara_unified.config.Settings` with:

- `voice_enabled: bool = False`
- `piper_service_url: str = "http://127.0.0.1:5000"`
- `piper_service_token: str = ""`
- `voice_timeout_seconds: float = 15.0`
- `voice_max_characters: int = 4000`

Environment variables:

- `SARA_VOICE_ENABLED`
- `SARA_PIPER_SERVICE_URL`
- `SARA_PIPER_SERVICE_TOKEN`
- `SARA_VOICE_TIMEOUT_SECONDS`
- `SARA_VOICE_MAX_CHARACTERS`

Configuration parsing MUST reject non-positive timeout and character-limit values.

## Piper Internal Service

Directory: `voice_service/`

Files:

- `voice_service/app.py`: FastAPI service, token enforcement, Piper model loading, synthesis endpoint, health endpoint
- `voice_service/requirements.txt`: isolated dependencies including `piper-tts`
- `voice_service/Dockerfile`: separate deployable image
- `voice_service/README.md`: deployment and model-volume contract

The service reads:

- `PIPER_MODEL_PATH`
- `SARA_VOICE_SERVICE_TOKEN`

The model file is not committed to Git. Deployment must mount or provision the `en_GB-cori-high.onnx` model and matching `.onnx.json` configuration. The service MUST fail startup if the model path or token is missing.

### Internal `POST /synthesize`

Headers:

- `X-SARA-VOICE-TOKEN: <token>`

Body:

```json
{
  "text": "...",
  "length_scale": 1.08,
  "noise_scale": 0.55,
  "noise_w_scale": 0.70,
  "volume": 0.95
}
```

The service returns WAV bytes only. It rejects missing/incorrect service tokens.

## Security Requirements

- Piper is a renderer, never an authority source.
- No client-provided filesystem path, model name, shell argument, URL, or executable is accepted.
- The SARA-facing API fixes the voice profile; arbitrary profile injection is prohibited in v1.
- The Piper internal service requires a shared service token and should be deployed on a private network.
- Full text is not persisted in SARA's audit event; only a SHA-256 digest and character count are recorded.
- Text length is bounded before it reaches Piper.
- Timeouts are mandatory on all SARA-to-Piper requests.
- Piper failure must not degrade SARA's text response or governance functions; voice returns a scoped error only.

## Dependency and Licensing Boundary

The main SARA `requirements.txt` remains free of `piper-tts`.

`piper-tts` is isolated under `voice_service/requirements.txt`. The Piper runtime currently declares GPL-3.0-or-later. The selected Cori voice model is distributed through the Piper voices repository and its model card identifies the training recordings as public-domain LibriVox material. Any external distribution of the Piper service image must be reviewed for GPL source/notice obligations before commercial release.

This design is an engineering boundary and is not a legal opinion.

## Testing

Core tests MUST prove:

- `sara_elegant_british_v1` cannot be overridden by a caller
- unauthorized synthesis is rejected
- empty and oversized text are rejected
- disabled voice returns `503`
- Piper timeout/unavailability is mapped to a scoped service error
- successful synthesis returns `audio/wav`
- the audit event contains a digest and character count, not raw spoken text
- `/v1/capabilities` includes `voice-synthesis`
- `/v1/voice/profile` reports the fixed profile metadata

Voice-service tests MUST prove:

- service token is required
- synthesis settings are bounded and parsed
- WAV bytes are returned from the Piper engine abstraction
- health is unavailable when the model is not ready

Tests for SARA core MUST use a fake in-process voice client so CI does not require the Piper model. Piper service unit tests MUST inject a fake engine so the 114 MB model is not required for ordinary repository CI.

## Deployment Acceptance

A production voice release is accepted only when all of the following are true:

1. Repository tests pass.
2. SARA core starts without Piper installed.
3. Voice disabled mode leaves existing SARA routes unaffected.
4. The Piper service starts separately with an explicitly provisioned model and service token.
5. One authenticated synthesis request returns a valid WAV file using `sara_elegant_british_v1`.
6. An unauthenticated call to the Piper internal endpoint is rejected.
7. SARA audit evidence records the synthesis digest without storing raw text.
8. ROAD/security verification for the release candidate remains passing.

## Out of Scope for This Release

- voice cloning
- speaker enrollment
- arbitrary user-selectable voices
- speech recognition / microphone input
- wake-word detection
- telephone integration
- emotion inference
- modifying SARA's reasoning based on audio characteristics

Those are separate future capabilities and must not be coupled to the first Piper synthesis release.
